## 开始之前

如果你还不了解 GLofter 项目，建议先看看[这个介绍](/posts/d3c9ab8a-7959-42d5-911b-e1c33cef5fb7/)，这样理解起来会更容易一些。

过去几个月，我作为个人开发者，基于 ArcBlock Blocklet 做了 GLofter 这个去中心化的摄影师工作室聚合平台。说实话，开发过程中遇到了很多在传统 Web2 应用里不会遇到的问题。比如怎么设计一个可持续的经济模型？怎么平衡去中心化和运营效率？怎么让代币真正有价值？

这些问题让我想了很多，今天想和大家聊聊。

## ABT 价格波动带来的定价难题

最开始设计 GLofter Hub 的订阅计划时，我直接用 ABT 作为定价单位。结果发现，ABT 的价格波动实在太大了。

这个月 10 ABT 可能相当于 3 美元，下个月 ABT 涨了，可能就相当于 30 美元了。用户根本没法判断订阅服务的真实成本，我也很难制定长期定价策略。

这让我开始思考：ABT 到底应该用来做什么？

我觉得 ABT 应该主要用于质押保证、治理参与和生态激励。而产品定价，应该用稳定币。这样才能给用户稳定的价格预期，降低决策成本，支持可持续的商业运营。

所以我建议 ArcBlock 需要推出原生稳定币。这可能是 ArcBlock DApp 生态发展的一个关键节点。有了稳定币，开发者才能设计可持续的商业模型，用户才能用熟悉的法币价值理解服务价格，更多 DApp 才能实现真正的商业化运营。

原生稳定币的推出将为 DApp 提供稳定的定价基础，让开发者能够设计可持续的商业模型。同时降低用户使用门槛，用户可以用熟悉的法币价值理解服务价格。更重要的是，这将推动生态繁荣，更多 DApp 能够实现真正的商业化运营，形成良性循环。

## 订阅计划限制配置的问题

为了内容质量和最大经济利益，我在 GLofter Hub 的订阅计划里设计了不同等级（基础版、专业版、高级版、企业版），每个等级有不同的资源限制，比如最大相册数、最大照片数等等。

但如果 Hub 运营者可以自由设置这些限制值，问题就来了。他们可能会把所有限制都设置成最大值，这样限制就失去了意义。不同 Hub 的限制标准不一致，用户也很难比较。而且缺乏限制约束，Studio 可能就不那么注重作品质量了。

所以在 GLofter 中，我设计订阅计划的限制配置由协议层定义，通过 NFT 实现，把公共约束限制保存在 NFT data 里，Hub 运营者不能修改。所有 Hub 使用相同的限制标准，保证公平性。限制值可以通过社区治理投票进行调整。

具体实现上，我通过 NFT 把 tier 限制值存储在 NFT data 中作为公共约束限制。Hub 运营者只能调整价格，不能调整资源限制。限制值的修改需要通过治理投票。

这样设计的好处是，所有 Hub 在相同的规则下竞争，通过限制激励 Studio 提交优秀作品，也能形成行业标准，便于用户理解和选择。同时，通过 NFT 存储这些配置，既保证了去中心化和透明性，又支持灵活的更新机制。

## Hub 容量限制与价格竞争

如果不对 Hub 的入住 Studio 数量进行限制，Hub 运营者可能会通过低价吸引大量 Studio，但服务质量下降。过度扩张导致资源分散，无法提供优质服务。最后形成恶性循环：低价导致低质量，低质量导致用户流失，用户流失又导致更低的价格。

在 GLofter 中，我设计了容量限制机制。每个 Hub 默认最多入住一定数量的 Studio（比如 1000 个），通过质押 ABT 可以增加容量上限。

这样设计有几个好处。容量有限，Hub 运营者就需要考虑定价策略，不能一味打价格战。为了吸引高质量 Studio，Hub 需要提升服务质量。质押 ABT 获得容量，也能体现 ABT 的经济价值。

具体来说，可以设计一个质押曲线。比如基础容量是 1000 studios，无需额外质押。质押 1 ABT 可以支持 1000 studios，质押 10 ABT 可以支持 2000 studios，质押 20 ABT 可以支持 2100 studios，以此类推。

可以用对数曲线或幂函数实现边际收益递减，比如 `capacity = base + a * log(stake + 1)` 或者 `capacity = base + a * stake^b`（b &lt; 1，比如 0.3）。这些参数（base、a、b 等）可以写到 NFT 中，通过 NFT data 进行配置和管理？我觉得这是个值得思考的问题。

## 质押曲线设计与 ABT 价值

如何设计合理的质押-容量曲线，既能激励 Hub 质押 ABT，又能体现代币的经济价值？

在 GLofter 中，我遵循几个设计原则。首先是边际收益递减，越往上，需要质押越多才能获得相同增量。其次是设置合理上限，比如最大容量上限 10000 studios。第三是灵活调整，质押可以随时增加，但减少需要等待解锁期。第四是治理参与，质押的 ABT 可以参与治理投票。

技术实现上，我通过 NFT 实现质押逻辑，在 NFT data 里设置质押值和容量值，可以更新 NFT，在有必要时进行更新。提供前端计算器，显示质押与容量的关系。支持质押增加和减少，减少需要解锁期。

这样设计的好处是，质押 ABT 可以获得实际收益（容量），形成经济闭环：Hub 需要质押，需求增加，ABT 价值提升。解锁期机制也能鼓励长期质押。

## 社区治理与罚没机制

如何通过社区治理保证 Hub 的服务质量？如何防止 Hub 运营者恶意行为？

在 GLofter 中，我设计治理的核心是社区监督、投票机制和透明公正。入住的 Studio 用户可以对 Hub 进行监督，通过投票决定是否对 Hub 进行罚没，所有治理过程公开透明。

罚没可以基于几个触发条件：服务可用性低于阈值（比如 95%）、响应时间超过阈值（比如 500ms）、数据丢失或损坏、恶意行为（比如拒绝服务、数据篡改）等。

投票机制可以设置投票门槛，比如需要一定比例的 Studio 用户投票（比如 30%），设置投票期（比如 7 天），根据严重程度决定罚没比例（部分或全部）。

关于罚没资金的分配，这里有个重要问题。罚没的资金会到指定的账户，由 ArcBlock 控制，开发者无法控制这些资金。我建议 ArcBlock 可以提供申请罚没分配的功能，用于补偿受影响的用户。罚没应该直接到用户，不经手开发者，这样既保证了资金的安全，也避免了开发者可能面临的信任问题。

还可以补充一些机制，比如申诉机制，Hub 可以对罚没决定提出申诉；信誉系统，长期稳定运行的 Hub 获得信誉加成；保险机制，Hub 可以购买保险，降低罚没风险。

这里我想提一个问题：投票机制、罚没分配、申诉机制等治理功能是否可以在协议层提供统一的公共解决方案？这样每个 DApp 不需要重复开发这些功能，可以大大降低开发量和难度，同时保证治理机制的一致性和可靠性。我建议 ArcBlock 可以提供一套标准化的治理协议或框架，让 DApp 开发者只需配置参数即可使用。

## 关于 Web3/DApp 的基本范式

在开发 GLofter 的过程中，我逐渐形成了对 Web3/DApp 基本范式的理解：

```javascript
Web3/DApp = Personal Node + Hub Node + App/Web + Stake + Stablecoin + Governance + NFT

```

让我简单解释一下各个要素的作用。

Personal Node（个人节点）负责用户数据主权、去中心化存储和身份认证（DID）。Hub Node（聚合节点）负责内容聚合与分发、服务发现和负载均衡。App/Web（应用层）负责用户界面、业务逻辑和跨链互操作。

Stake（质押机制）用于服务保证、治理参与和经济激励。Stablecoin（稳定币）作为定价基础、支付媒介，保证价值稳定。Governance（治理）包括 DAO 治理、提案投票和协议升级。

NFT（非同质化代币）可以存储公共约束限制、质押参数等协议配置，也可以存储质押值、容量值等状态数据。支持通过更新 NFT data 来调整配置和状态，配置和状态存储在链上，保证透明和不可篡改。通过质押还可以实现 Hub 服务发现，质押的 Hub 可以在链上被发现和验证，形成去中心化的服务注册机制。

最后是 Verifiability（可验证性），包括链上证明、数据完整性和服务可审计。

这个范式可以为开发者提供清晰的架构指导，推动形成标准化的 DApp 开发模式，相比传统互联网，Web3 范式具有去中心化、可验证、用户主权等优势。

## 在开发 GLofter 的过程中，我深刻认识到几个问题

稳定币是 DApp 商业化的基础，没有稳定币，很难实现可持续的商业运营。协议层治理是公平竞争的保障，关键配置应该由协议层定义，而不是运营者自由设置。NFT 是配置和状态存储的理想载体，通过 NFT data 存储公共约束限制、质押参数、容量值等，既保证了去中心化和透明性，又支持灵活的更新机制。通过质押还可以实现 Hub 服务发现，形成去中心化的服务注册机制。质押机制是代币价值的重要体现，通过质押获得实际收益，形成经济闭环。社区治理是生态健康的关键，通过治理机制保证服务质量，防止恶意行为。统一公共解决方案可以降低开发门槛，投票机制、罚没分配、申诉机制等治理功能如果能在协议层提供统一方案，将大大降低 DApp 开发难度。

我相信，通过社区的深入讨论和共同努力，ArcBlock 生态能走向成熟，ABT 能发挥真正的价值。NFT 作为配置和状态存储的载体，统一治理框架作为降低开发门槛的工具，都将成为 ArcBlock 生态发展的重要推动力。

让我们共同推动 ArcBlock 生态的发展！
