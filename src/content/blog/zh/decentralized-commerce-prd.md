## 一、项目概述（Overview）

**项目名称：**
🌐 **DeCom Network** — 去中心化电商生态

**核心理念：**
让每个商家都能**独立拥有自己的店铺（Shop Blocklet）**，
每个社区或媒体都能**自由运营主题商城（Mall Hub）**，
用户通过**统一的 DeCom App** 发现、购买、收藏、评价、再创作，
形成一个“**去平台化、分收益、跨地域**”的电商网络。

---

## 二、系统构成（Architecture Overview）

| 模块  | 名称  | 角色定位  | 类比  | 主要技术形态  |
|---|---|---|---|---|
| 🏪 商家端  | **DeShop Blocklet**  | 每个商家自建的独立电商站  | Shopify 店铺 / 小红书店铺  | Blocklet DApp（商家自托管）  |
| 🏙️ 聚合端  | **DeMall Hub**  | 社区型、品类型商城聚合节点  | 淘宝频道 / 京东联盟 / 小程序聚合  | Blocklet DApp（开放接入）  |
| 📱 用户端  | **DeCom App**  | 普通消费者的购物与发现入口  | 小红书 / Etsy App  | 跨 Hub 的客户端（Web + Mobile）  |

## 三、目标与愿景（Vision &amp; Goals）

**核心愿景：**

> 去中心化重塑电商：让“交易”回归商家与消费者，
> 平台（Hub）不再掌控数据，而成为可替换的流量节点。
> 

**短期目标（1 年内）：**

- 部署 ≥10,000 个独立 DeShop Blocklet
- 建立 ≥500 个活跃 Mall Hub（按品类/地区运营）
- App 日活 ≥50,000
- 付费交易成功率 ≥98%
- 平均交易分成：商家 85% / Hub 10% / 网络 5%

**长期目标（3–5 年）：**

- 构建全球去中心化电商联盟标准（DeCom Protocol）
- 实现链上物流与身份验证（DID + VC）
- 支持 AI 生成营销内容与动态定价模型

## 四、市场分析（Market Analysis）

### 4.1 市场规模与趋势

- 全球电商市场规模 2025 年预计达 **$8.1 万亿美元**；
- 小型卖家占交易量 60%+，但利润率最低（平台抽成 + 广告费）。
- 去中心化技术（DID、智能合约、IPFS、Web3 支付）日趋成熟，允许独立卖家低成本建站。

**机会点：**

- 独立品牌（DTC）增长迅猛；
- 用户更重视**真实与可验证的来源**；
- Web3 社区原生支持“收益分配与透明化”。

### 4.2 竞争格局对比

| 类型  | 代表  | 优势  | 局限  | DeCom 差异  |
|---|---|---|---|---|
| 平台型电商  | 淘宝 / 亚马逊  | 流量集中、生态成熟  | 抽成高、封闭、数据锁定  | 自托管 + 去平台化分发  |
| 独立建站  | Shopify / Wix  | 灵活、自定义  | 缺乏流量入口  | 可自动推送至 Hub  |
| Web3 电商  | Zora / Manifold  | 上链可溯源  | 缺少电商体验、支付门槛高  | 混合模式（链下结算 + DID 认证）  |

## 六、核心功能需求（Functional Requirements）

### A. 🏪 DeShop Blocklet（商家端）

**主要使命：自建独立电商节点，可推送到多个 Hub 获得流量**

| 模块  | 功能描述  |
|---|---|
| **A1. 商店初始化**  | 安装 Blocklet、一键生成品牌主页、选择主题（自定义模板引擎）。  |
| **A2. 商品管理**  | 商品分类、图片/视频上传（IPFS+S3 混合存储）、SKU 属性、库存、价格策略（动态/区域/折扣）。  |
| **A3. 订单与支付**  | 支持多支付渠道（法币、加密、稳定币），自动分账；订单状态、物流接口。  |
| **A4. Hub 推送**  | 可将商品/店铺推送到多个 Hub，Hub 审核后上架；分销抽成比例在协议层签署。  |
| **A5. 数据与分析**  | 访客来源、订单漏斗、Hub 转化率、结算报告。  |
| **A6. 合规与隐私**  | 商家实名认证（DID + VC）、销售条款、退款机制。  |

---

### B. 🏙️ DeMall Hub（商城端）

**使命：聚合与分发商品，建立垂直主题市场，赚取流量与分成**

| 模块  | 功能描述  |
|---|---|
| **B1. 入驻与审核**  | 接收 DeShop 的推送申请，自动或人工审核；黑名单过滤、品类规则。  |
| **B2. 商品聚合与分类**  | 自动构建目录与搜索索引；按标签、价格、地区、销量筛选。  |
| **B3. 分销与抽成**  | Hub 可设抽成比例，系统自动结算。可开放“联盟营销链接”。  |
| **B4. 内容营销**  | Hub 可自建内容页（专题、榜单、测评、短视频）连接商品；AI 自动生成文案。  |
| **B5. 订单分账**  | 交易在 DeShop 完成，Hub 获得分润；若在 Hub 内完成支付，则走托管模式。  |
| **B6. API 与 SDK**  | Hub 可向第三方 App 暴露商品/订单 API；支持插件生态。  |

---

### C. 📱 DeCom App（用户端）

**使命：统一入口，探索多 Hub 的独立品牌世界**

| 模块  | 功能描述  |
|---|---|
| **C1. 探索与发现**  | 聚合所有 Hub 的商品与内容；按兴趣/地区推荐；AI 个性化算法。  |
| **C2. 购买体验**  | 支持 Web2（银行卡/PayPal）与 Web3（钱包）支付；本地货币显示。  |
| **C3. 用户身份**  | 基于 DID 登录；历史订单、收藏、评价；数据保存在用户侧。  |
| **C4. 创作者返利**  | 用户可分享链接成为二级分销员；佣金结算自动化。  |
| **C5. 商家控制台（App 内）**  | 轻量管理工具：上架、库存调整、收益查看。  |

## 七、经济模型（Tokenomics）

| 角色  | 收益来源  | 支付形式  |
|---|---|---|
| 商家（DeShop）  | 商品销售额的主要部分  | 法币 / 稳定币 / Token  |
| Hub 运营者  | 抽成 + 推广奖励  | 按订单比例  |
| 用户  | 返利 + 空投 + 内容激励  | Token / 折扣券  |
| 网络开发者  | 应用商店上架收入 / API 使用费  | Platform Fee  |

**默认分账结构：**

> 80% 商家 + 15% Hub + 5% 平台基础费（可治理修改）
>

## 九、非功能需求（NFR）

- **性能**：商品搜索延迟 &lt;1s；订单确认回调 &lt;5s
- **可用性**：服务可用性 99.9%；区块链交互支持断点重试
- **安全性**：交易签名、Webhook 验证、防篡改日志
- **隐私合规**：GDPR/CCPA；数据加密；KYC 分级验证
- **可扩展性**：多 Region 部署、Hub 去中心化注册协议（Hub Directory Registry）
- **兼容性**：S3 / IPFS 混合存储；支付插件可替换

## 十、对比与创新点

| 项  | 传统电商  | DeCom 模式  |
|---|---|---|
| 数据归属  | 平台所有  | 商家自持  |
| 成本结构  | 广告+抽成  | 自托管+Hub 按需分成  |
| 上架门槛  | 受限平台规则  | 开放注册（可验证身份）  |
| 流量分发  | 算法封闭  | 可加入多个 Hub 联盟  |
| 营销能力  | 中心化广告  | 内容协作 + 用户返利生态  |
| 国际化  | 平台限制  | 多语言多币种，由节点自定义  |

## 十一、技术架构（摘要）

- **前端**：Next.js / React / Tailwind / shadcn
- **服务端（Blocklet SDK）**：Node.js + SQLite / Postgres
- **去中心化基础**：ArcBlock ABT Network + DID + VC + Token Split
- **存储**：S3 + IPFS 混合（图片、商品描述）
- **支付**：Stripe / Coinbase Commerce / ArcPay
- **协议层**：DeCom Registry（Hub 列表注册 + 智能合约分账）
