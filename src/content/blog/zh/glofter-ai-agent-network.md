过去一段时间，我一直在思考 GLOFTER 应该如何发展。

GLOFTER 最初的设想，是建立一个去中心化的摄影平台。

摄影师不再只是某个平台里的一个账号，而是拥有自己的 Studio；每一个 Studio 都可以独立运行；摄影师可以管理自己的作品、相册、服务和客户，并通过 Hub 被发现和连接。

在这个模型中，ArcBlock 提供了非常重要的基础设施：

Blocklet 提供应用运行环境，DID 提供身份，NFT 可以用于权益和激励机制，Hub 可以承担发现和连接的角色。

但是，随着 AI Agent 时代的到来，我开始意识到：

**GLOFTER 可能不应该只是一个去中心化的摄影平台，而可以进一步成为一个 AI Native 的摄影师网络。**

而这其中，一个非常重要的变化，就是：

**未来的 GLOFTER，不仅仅是“摄影师使用的软件”，还可以拥有属于摄影师自己的 AI Agent。**

---

## 一、从“摄影师使用软件”到“AI Agent 代表摄影师工作”

传统互联网平台的逻辑是：

> 用户登录平台 → 创建个人主页 → 上传作品 → 管理内容 → 回复客户 → 接受订单。
> 

在这种模式下，所有事情都需要摄影师自己完成。

摄影师需要维护自己的主页，需要整理照片，需要给照片添加标题和标签，需要回复客户，需要处理预约，需要推广自己的作品。

这意味着，摄影师不仅是一个创作者，同时还必须成为一个内容运营者、客服、营销人员甚至销售人员。

对于一个独立摄影师来说，这些事情往往比拍摄本身更加消耗时间。

AI Agent 的出现，可能会改变这种模式。

未来，一个摄影师进入 GLOFTER 后，可以拥有一个属于自己的：

**GLOFTER AI Photographer Agent**

这个 Agent 不只是一个聊天机器人。

它可以理解摄影师是谁，知道摄影师擅长什么，了解摄影师的作品风格，知道摄影师提供哪些服务，也能够代表摄影师与外界进行交互。

例如：

> “我是一个主要拍摄人像和旅行摄影的摄影师。”
> 

Agent 可以逐渐理解：

- 摄影师的身份
- 摄影师的拍摄风格
- 摄影师的作品
- 摄影师的摄影经历
- 摄影师所在城市
- 摄影师的服务范围
- 摄影师的价格体系
- 摄影师的可预约时间
- 摄影师的客户偏好

这样，摄影师不再只是一个静态的 Profile。

而是拥有了一个能够持续工作的数字化 Agent。

# 二、GLOFTER AI Photographer Agent 可以做什么？

我认为，GLOFTER Agent 的第一个阶段，并不需要追求复杂的自主决策。

最重要的是让 Agent 成为摄影师的：

> **AI Assistant + Digital Representative**
> 

例如，一个摄影师拥有自己的 GLOFTER Studio。

他的 Agent 可以帮助完成以下工作。

### 1. 自动管理摄影作品

摄影师上传一组照片后，Agent 可以自动分析照片内容。

例如：

> “这是一组在京都拍摄的街头摄影作品。”
> 

Agent 可以自动生成：

- Album Title
- Description
- Tags
- Location
- Shooting Date
- Camera
- Lens
- Photography Style

甚至可以根据摄影师自己的风格，对内容进行重新编辑。

摄影师只需要确认：

> “发布。”
> 

整个过程就完成了。

---

### 2. 自动整理摄影作品

随着摄影师积累越来越多的照片，Agent 可以帮助管理整个 Studio。

例如：

> “帮我找出过去一年拍摄的所有城市夜景作品。”
> 

Agent 可以搜索摄影师自己的作品库。

或者：

> “帮我创建一个适合展示给商业客户的作品集。”
> 

Agent 可以从摄影师已有的作品中自动筛选，并创建新的 Album。

这时候，AI Agent 实际上已经成为了摄影师的：

**AI Photo Manager**

---

### 3. 自动维护摄影师的 Studio

未来，摄影师可能只需要告诉 Agent：

> “我最近开始提供婚礼摄影服务。”
> 

Agent 可以协助完成：

- 更新 Studio Profile
- 创建 Wedding Photography 服务
- 设置服务价格
- 创建服务介绍
- 更新 FAQ
- 添加案例作品
- 更新预约规则

摄影师不需要打开十几个管理页面。

只需要告诉 Agent：

> “帮我把 Studio 更新一下。”
> 

Agent 完成剩下的工作。

---

### 4. 成为摄影师的 AI 客服

假设一个客户来到摄影师的 Studio。

客户问：

> 你提供洛杉矶婚礼摄影吗？
> 

Agent 可以回答：

> 提供。我主要提供婚礼、人像和纪实摄影服务。你可以查看我的婚礼摄影作品集。如果你告诉我婚礼日期和地点，我可以帮你查询档期。
> 

客户继续问：

> 2026 年 10 月 10 日还有时间吗？
> 

Agent 可以检查摄影师的预约系统。

如果有空档：

> 这个日期目前有档期。
> 

如果没有：

> 这个日期已经被预约，我可以帮你查看附近的其他日期。
> 

这已经不是简单的 FAQ。

Agent 正在代表摄影师与客户进行真实的业务交互。

# 四、为什么 ArcBlock 非常适合构建这样的 Agent？

我认为，AI Agent 真正大规模发展后，会遇到一个非常重要的问题：

**Agent 到底是谁？**

如果一个 Agent 可以代表一个人、一个组织、一个 Studio，甚至一个商业实体，那么它需要：

- 身份
- 权限
- 数据
- 资产
- 工具
- 信任
- 可验证性

这恰恰是 ArcBlock 长期积累的能力可以发挥价值的地方。

一个 GLOFTER Photographer Agent 可以拥有自己的 DID。

例如：

```javascript
Photographer
      │
      ↓
   DID Identity
      │
      ↓
Photographer Agent
      │
 ┌────┼─────┐
 ↓    ↓     ↓
Studio Album Service
      │
      ↓
     Hub

```

摄影师本人拥有自己的 DID。

Studio 可以拥有自己的 DID。

Agent 也可以拥有自己的身份标识。

这样，未来就可以形成一种更加清晰的关系：

> **人拥有 Agent，Agent 代表人，Agent 操作 Studio，Studio 连接 Hub。**
> 

这比传统平台中的：

> 用户名 + 密码 + 平台账号
> 

具有更强的可组合性。

# 五、Agent + DID：AI 时代的数字身份

传统 AI Agent 最大的问题之一，是：

> Agent 可以行动，但它是谁？
> 

如果一个 Agent 调用了一个 API，我们知道是一个程序调用了 API。

但如果未来 Agent 代表一个摄影师与客户签订服务协议，或者代表一个 Studio 接受预约，那么“身份”就变得非常重要。

DID 可以成为 Agent 世界中的身份基础设施。

例如：

```javascript
Photographer DID
       │
       ├── Owns
       │
       ↓
Studio DID
       │
       ├── Operates
       │
       ↓
Photographer Agent DID
       │
       ├── Uses
       │
       ↓
Studio Tools

```

这样可以建立清晰的身份和授权关系。

Agent 不一定拥有摄影师的全部权限。

它可以拥有不同级别的权限：

```javascript
读取作品       ✓
创建 Album     ✓
修改 Profile   ✓
回复客户       ✓
查询预约       ✓
创建订单       ✓
退款           ✕
资金转账       ✕

```

这意味着未来可以形成：

> **DID + Agent + Permission**
> 

这样的基础模型。

Agent 不只是“聪明”，还必须是：

**可识别、可授权、可验证、可追踪。**

我认为，这将是区块链技术与 AI Agent 真正产生深度结合的一个重要方向。

# 六、Blocklet 可以成为 Agent 的“身体”

如果把 Agent 比作“大脑”，那么 Agent 还需要一个可以运行和执行任务的环境。

这时候，Blocklet 就可以成为一个非常有意思的基础设施。

例如：

```javascript
GLOFTER Photographer Agent
           │
           ↓
        Blocklet
           │
    ┌──────┼──────┐
    ↓      ↓      ↓
  Studio  Album  Booking
    │      │      │
    └──────┼──────┘
           ↓
         Hub

```

Agent 负责：

> 理解、规划、决策。
> 

Blocklet 负责：

> 执行、存储、提供 API 和服务。
> 

例如：

> “帮我创建一个新的旅行摄影 Album。”
> 

Agent 可以调用 Blocklet 提供的 API：

```javascript
createAlbum()
uploadPhotos()
generateMetadata()
updateProfile()
publishToHub()

```

Agent 不需要直接操作底层数据库。

它通过标准化 Tool 调用 Blocklet 的能力。

这就形成：

> **Agent → Tool → Blocklet**
> 

的架构。

如果未来 ArcBlock 的 Agent Framework 可以很好地连接 Blocklet，那么我认为这会非常有潜力。

因为 Blocklet 本身就非常适合作为：

> **Agent 的可组合能力单元。**
>

# 结语：GLOFTER 不只是一个摄影平台

GLOFTER 的最初目标，是让摄影师拥有自己的 Studio。

而 AI Agent 的出现，让这个目标可以进一步延伸。

未来，一个摄影师拥有的可能不只是一个 Studio，而是一个：

> **能够理解摄影师、管理作品、服务客户、参与业务、连接网络的 AI Photographer Agent。**
> 

摄影师负责创作。

Agent 负责运营。

Blocklet 负责执行。

DID 负责身份。

Hub 负责发现和连接。

而 ArcBlock Agent Framework，则有机会成为连接这一切的基础设施。

我认为，GLOFTER 的下一步不应该只是“加入 AI”。

而应该思考：

> **如果 GLOFTER 从第一天开始就是为 AI Agent 设计的，它会是什么样？**
> 

也许未来的 GLOFTER，不再只是一个让人寻找摄影师的平台。

而是一个由无数 Photographer Agent 组成的全球摄影网络。

在那里，摄影师拥有自己的身份、自己的 Studio、自己的作品、自己的数据和自己的 Agent。

人和人之间可以交流。

人和 Agent 可以交流。

Agent 和 Agent 也可以交流。

而这一切，都建立在一个开放、可组合、去中心化的网络之上。

**这可能就是 GLOFTER 与 ArcBlock Agent Framework 结合后，我最期待看到的未来。**
