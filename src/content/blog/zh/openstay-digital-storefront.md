## 用三句话说清楚我们在想什么

1. **每一家**宾馆、旅店、民宿，都可以有一个**真正属于自己的**预订网站和客人数据，而不是完全依附在某一个全球 App 里。
2. **很多个**这样的「单店」可以自愿加入**不同的聚合平台**（下面称为 **Hub**）。Hub 负责帮你被更多人看见、做资质把关，并收取**合理的订阅费或订单分成**。
3. **旅客**可以像选电视台一样，**选择自己信任的 Hub** 来浏览和预订；如果客人本来就认识你家，也可以**直接打开你家的页面**，不经过任何中间商——这时不会有第三方替你审核信息，风险由客人自己判断。

我们希望这套模式能在全球逐步生长：**规则开放、参与者多元、单店有尊严、中间层可替换。**

## 为什么需要一种新的想象

今天大多数人订房，离不开少数几个大型在线平台（OTA）。它们解决了「找房方便」的问题，但也带来常见困扰：

- **佣金高**：中小旅店利润被抽走一大块，议价困难。
- **品牌弱化**：客人记住的是平台，未必记住你的店名和故事。
- **数据不在你手里**：房型、图片、评价、客户关系往往沉淀在平台侧，你想换个渠道时很被动。
- **信任难辨**：刷单评价、图文不符等问题，用户很难分清是「平台担保」还是「店家自律」。
- **各国规则不同**：旅馆执照、短租政策、税务千差万别，「一个全球 App 管一切」往往要么管得太死，要么本地合规跟不上。

OpenStay 不是要一夜之间打倒谁，而是提出一种**结构上的补充**：让**店家**、**聚合方**、**旅客**三方都有更多选择。

## OpenStay 是什么：一个比喻

想象一条商业街：

- **你家旅店** = 街边**独立门店**。你有自己的招牌、装修、价目表和收银方式，客人进店直接和你打交道。
- **Hub** = **商场或旅游集散中心**。它把很多店集中展示、做统一导购，还可能统一安检（审核资质）。商场收租金或从流水里抽成。
- **旅客** = 逛街的人。他可以**进商场**（选一个 Hub，在里面比价、筛选），也可以**直接走进某一家临街小店**（只访问那家旅店的页面）。

OpenStay 主张：**门店永远是你的**；**商场可以有很多家**，而且你可以同时入驻多家或只开一家店——而不是全世界只剩一个商场。

| **角色**  | **可能是谁**  | **最关心什么**  |
|---|---|---|
| **旅店方**  | 宾馆、连锁分店、民宿、青旅  | 自有品牌、合理费用、多平台分发、客人关系在自己手里  |
| **Hub 运营方**  | 地方协会、创业团队、垂直领域 KOL、企业差旅服务商  | 把好入驻质量、做出特色选品、获得稳定收入（订阅 + 分成等）  |

| **技术与生态伙伴**  | 开发者、支付公司、设计公司  | 主题模板、插件、合规工具、数据分析（在保护隐私前提下）  |

## 旅店方会得到什么（单店「数字店面」）

下面这些能力，是按**从易到难**排列的讨论清单，实际落地可以分阶段做。

**门面与品牌**

- 自己的预订页面（可用自己的风格、多语言），像官网一样展示故事和照片，而不是淹没在平台统一模板里。
- 房型介绍：面积、床型、可住人数、设施（网络、空调、停车等）。
- 高质量图片与可选短视频；鼓励标注图片来源，减少纠纷。

**库存与价格**

- 日历：哪些日期可订、关房维护、旺季调价。
- 价格规则：周末价、节假日、最少住几晚、取消政策（灵活 / 中等 / 严格）。

**订单与沟通**

- 客人选房、选日期、填入住人、确认规则后生成订单。
- 店家接单或拒单、协商改期改价时留下记录、处理退款申请。
- 用邮件、短信等方式提醒（具体能力取决于实现阶段）。

**信任展示（可与 Hub 配合）**

- 展示证照或资质信息的方式需要符合当地法律，可采用「可验证存证」等方案，细节留给合规与产品共创。
- 页面上可以写：本店已加入哪些 Hub，方便客人理解「谁在帮你做过额外审核」。

## Hub 会得到什么（聚合与审核）

Hub 不是「又一个垄断平台」，而是**可竞争的服务商**：旅客可以换别的 Hub，旅店也可以换 Hub 或同时加入多个（若规则允许）。

**入驻与审核**

- 旅店申请加入时，Hub 可以要求提供资料，做人工或辅助审核（例如证照抽查、黑名单比对）。
- 审核通过才进入「推荐列表」；不通过或违规可下架，并应有申诉渠道。
- 可分档服务（例如基础档 / 进阶档）：档位越高，可能包含更多曝光、更快同步、更多推荐位——对应不同费用。

**展示与搜索**

- 把已通过审核的旅店信息汇总成**可搜索的目录**：目的地、日期、价格区间、设施、标签（如亲子、宠物友好）。
- 详情页可以只做「摘要 + 跳转回店家页面完成预订」，也可以做「在 Hub 内完成预订」——两种模式法律责任和佣金结构不同，需要分阶段和社区讨论。

**收入方式（可组合）**

- **订阅制**：旅店为「待在 Hub 里、被索引、被推广」付月费或年费。
- **分成制**：通过 Hub 带来的订单，按约定比例分成。
- **增值服务**：广告位、代运营、多语言包装、匿名化的行业洞察报告等。

**风控与治理**

- 用户举报、调查、下架与申诉流程要清楚、可审计。
- 对于「客人直接打开某旅店链接、不经过 Hub」的情况，Hub 应明确：**那一路径没有经过本 Hub 审核，本 Hub 不对信息真实性背书。**

## 旅客会得到什么

**两种逛法**

1. **推荐逛法（类似进商场）** 先选一个你信任的 Hub（例如专注某国、某类民宿、或某语言社区），在里面搜索、筛选、比较。列表里的旅店一般经过该 Hub 的审核，**多一份安心，但不是法律意义上的绝对担保**——具体以各 Hub 公示规则为准。
2. **直达逛法（类似熟人介绍）** 你已有店家链接或二维码，直接进入那家旅店的页面。这时**没有第三方替你筛过一遍**，页面上应有显眼提示，由你自己判断是否信任该店家。

**基本流程**

发现 → 看详情 → 下单 → 管理订单 → 入住后评价。
若使用「数字钱包」一类工具登录，可以拥有**跨店、可携带的身份**（不必每个网站重新注册一套），并减少恶意刷单评价的空间——实现深度可以分阶段推进。

## 和「传统大平台」相比，优势在哪里（通俗版）

| **方面**  | **常见大平台**  | **OpenStay 构想**  |
|---|---|---|
| 谁家说了算  | 往往一家规则定天下  | **很多个 Hub 竞争**，规则可不同，店家可迁移  |
| 你家品牌  | 容易变成「平台上的某一间」  | **优先突出店家自己的店名与故事**  |
| 数据与关系  | 常留在平台  | **以店家自有系统为主**，更利于长期经营  |
| 佣金压力  | 议价空间小  | **Hub 可替换**，费用结构可谈判、可分层  |
| 全球与本地  | 一套产品打全球，本地合规难  | **区域 Hub 做本地合规**，整体仍互联互通  |
| 创新  | 新功能要等平台排期  | **单店可先试**：会员权益、连住套餐、本地体验打包等  |

**所谓「颠覆性」**，不是说马上消灭中间环节，而是：**中间环节不再只有一家、不再锁死数据与品牌**——让市场有空间长出更健康的结构。

## 技术底座（用最短的话说明白）

OpenStay 的设想建立在 **ArcBlock** 等支持的 **Blocklet** 思路上：可以把每个旅店、每个 Hub 都做成**可独立部署、独立运营的小应用**，像一个个「数字店面」和「数字商场」，彼此用**开放约定**连接，而不是全部挤在同一台别人的服务器逻辑里。

**用非技术语言概括：**

- **可验证的身份**：店家和 Hub 的运营者可以用「数字身份」证明「是这个主体在操作」，减少冒充。
- **公开目录（可选）**：愿意公开的 Hub 和旅店节点，可以出现在一个**全球可查的列表**里，就像电话簿，但带「谁质押了信誉」一类机制，帮助用户判断优先看谁。（实现细节由社区与工程师共同设计。）
- **委托付费**：旅店授权 Hub 按约定扣订阅费或分账，规则事先写明，减少扯皮。

**你不需要记住这些词**，只要知道：目标是**透明、可迁移、多主体**，而不是再造一个黑箱。

## 必须直面的难题（欢迎社区一起回答）

1. **旅馆业执照、短租政策**：Hub 审核到什么程度？算不算「交易平台」？法律责任怎么划界？
2. **钱怎么收、税怎么报**：跨国订单的支付、外汇、发票，由店家、Hub 还是支付公司牵头？
3. **纠纷怎么办**：退款、到店无房、图文不符——线上规则 + 线下仲裁如何衔接？
4. **隐私与安全**：客人身份证、联系方式如何最小化收集与加密保存？
5. **体验速度**：全球分布的很多小应用，搜索和打开页面够不够快？这需要工程上持续优化。

这些没有标准答案，**正是适合在社区里公开讨论的原因。**

## 若要做，建议分几步走（非承诺路线图）

| **阶段**  | **做什么（白话）**  |
|---|---|
| 第一步  | 把想法拆成「法律上 Hub 算什么」「钱怎么走」几个子话题，收集反馈。  |
| 第二步  | 做出**一家旅店能用**的完整小闭环：房型、日历、下单、店家后台。  |
| 第三步  | 做出**第一个 Hub**：审核、列表、搜索，让多家店被一起看到。  |
| 第四步  | 做出**旅客用的 App 或网页**：能选 Hub、能搜、能订。  |
| 第五步  | 订阅与分成、评价防刷、举报申诉做扎实。  |
| 第六步  | 多 Hub、多地区、主题装修、插件生态。  |

实际顺序可能调整；**小而能用的试点**比「一次画满大饼」更重要。
